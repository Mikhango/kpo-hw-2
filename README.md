# Financial Accounting Module Demo

Консольное приложение на C++, демонстрирующее доменную модель модуля «Учет финансов».

## Возможности

- Управление банковскими счетами, категориями и операциями через фасады.
- Автоматическое обновление баланса при добавлении операций.
- Аналитика: расчет итогового баланса и группировка по категориям.
- Импорт данных из CSV через шаблонный метод, с сохранением ссылочной целостности.
- Экспорт данных в форматы CSV, JSON, YAML с использованием паттерна Посетитель.
- Измерение времени пользовательских сценариев (паттерн Команда + Декоратор).

## Использованные принципы и паттерны

- **SOLID**:
  - *Single Responsibility Principle*: фасады и репозитории изолируют ответственность за работу с доменной моделью.
  - *Open/Closed Principle*: новые экспортёры/импортёры добавляются расширением абстрактных классов.
  - *Dependency Inversion Principle*: взаимодействие построено через интерфейсы `IRepository`, `IOperationRepository`, `IAnalyticsService`.
- **GRASP**: высокая связность внутри фасадов и сервисов, слабое зацепление за счет использования интерфейсов и DI контейнера.
- **Паттерны GoF**:
  - *Фабрика*: `DomainFactory` создает валидные доменные объекты и управляет идентификаторами.
  - *Фасад*: `AccountFacade`, `CategoryFacade`, `OperationFacade`, `AnalyticsFacade` концентрируют бизнес-логику.
  - *Команда + Декоратор*: команды пользовательских сценариев оборачиваются в `TimedCommandDecorator` для измерения времени.
  - *Шаблонный метод*: `DataImporter` реализует общий алгоритм импорта, конкретные форматы (`CsvDataImporter`, `JsonDataImporter`, `YamlDataImporter`) переопределяют этап парсинга.
  - *Посетитель*: экспорт строится через `DataExportVisitor` и его реализации для разных форматов.
  - *Прокси*: `CachingOperationRepositoryProxy` и `AnalyticsCacheProxy` кэшируют операции и результаты аналитики.
  - *DI контейнер*: `DIContainer` управляет зависимостями сервисов.

## Сборка и запуск

```bash
cmake -S . -B build
cmake --build build
./build/financial_app
```

После запуска приложение создаст примеры данных, выполнит аналитику и сохранит выгрузку в каталоге `data/`.

## Структура проекта

- `include/financial/` — заголовочные файлы доменной модели и сервисов.
- `src/` — реализации и точка входа.
- `data/` — каталог для экспортированных файлов.
- `CMakeLists.txt` — конфигурация сборки.
